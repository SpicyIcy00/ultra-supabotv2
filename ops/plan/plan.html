The build plan, session by session

Thirteen sessions in four phases, one card each, every prompt the same shape so a cold session can't go wrong. The plan lives in ops/NOW.md; this page is the readable copy. Nothing here is a rebuild. Every card is the next fix to the surface that exists, measured against a number.

How you run it. Two prompts and a habit.

1 · Every morning, five minutes on the live build

Use George for real. The moment something is wrong, say it in your own words. Claude writes it down and does not start fixing.

Log this: asked "how are we doing" — the answer disappeared

A report that has no card yet is picked up with the generic prompt. Once a report HAS a card, name the card instead, or the session takes whatever is top of the log that day.

Read ops/NOW.md. Fix the top item in the dogfood log.
2 · Every session, one card

This is the whole prompt. NOW.md holds the card's detail, the rules, and the close-out format. If the dogfood log has anything Open, it does that first, by its own rule.

Read ops/NOW.md. Do the next card.

To name a card instead:

Read ops/NOW.md. Do card P1.f.
3 · When the close-out says green, you say push

A session ends with suites, the card's number before and after, and what is not done — and then, last on screen, a short numbered list of what is yours to do. Added 14 September, when you read a full close-out and asked what you needed to do. If there is nothing, it says so in one line. If suites passed and there is no migration, say the word and dogfood the next morning is on the new build.

push

If the close-out names a migration, push in the morning and watch /health for five minutes.

4 · When anything is run at all

Three cards out of thirteen, $4.53 in total. A live run happens only when a card changes the trust machinery itself — the prompt, the compose grammar, the figure gate, the notice path, or how hard George thinks — or at a phase close. Everything else rides the close.

This was tightened on 13 September after you asked whether so many cards needed one. Six were dropped, and not to save money: they sat where a regression was speculative and the gate questions could not have seen it anyway. The cost is attribution. A regression that lands in a riding card shows up at the close with up to eight cards behind it.

5 · Three ways it gets cheaper

Measured: 72% of a run is round trips, not questions. Cache writes and reads scale with how many times George thinks, and the four gate questions are only 63c of a $1.51 run. So cutting questions barely helps.

Replay instead of re-running. Every trust check is a function of the answer and the rows, so a card that changes only a check needs no live turn at all. That is built and proved: tests/evals/corpus.py, replayed against your last run, found the leaked column name on its own for nothing.

The effort card was supposed to be the real discount and was not. Built on 14 September, it cut round trips by a third and the answer by eight seconds — and the same eleven questions still cost $1.62. Fewer, deeper turns is not fewer tokens: he writes less and thinks more in one go. So $1.51 stays the price of a run, and the saving that card bought is your waiting time, not money.

Keep a pair of runs inside an hour, so the second reads the cached prompt instead of paying to write it again.

6 · When to switch model

Opus 5 builds every card. You switch to Fable 5.1 in exactly two situations, and both are marked on the cards below.

First, after each phase closes — P1.✓, P2.✓, P3.✓ each end with a separate review session. Second, any time a close-out surprises you: it claims a number you doubt, or says something is done that does not feel done.

Read ops/NOW.md and ops/DECISIONS.md. Review the last close-out against the code. Name what to distrust.

Never switch mid-card. One session, one model.

7 · Friday, the sweep

Errors nobody reported. George files his own. One session.

Read ops/NOW.md, then run the weekly sweep and the cost report.

what the pills on each card mean

#2 · #6

Which of your own 26 features this card serves, by their number in your list. #2 is the transforming workspace, #6 is contextual conversation. The full list is ops/STANDARD.md, and the Ideal UI's "26" button maps every one.

trust

Three cards serve no feature on your list, and say so rather than borrowing a number they do not serve. They serve the plan itself: trust keeps George honest about figures, speed makes turns cheaper and shorter, the measure fixes the suite every other number is reported through.

no eval

Costs nothing extra. The card cannot change what the model sees or how it thinks, so there is no reason to run the questions at all. Most cards are this.

no eval

Rides the phase close. Either the card cannot change what the model sees, or the gate scenarios could not see the change even if it did. A new comparison is a capability no gate question asks about, so running one there proves nothing.

eval · subset

The trust gate: four fixed questions, $0.63 measured. No card in the plan carries this any more, since the one that did became free. It is what you run for an unplanned change that touches the prompt, which is usually a dogfood fix rather than a card. Not questions picked by feel. They are the ones that catch an unsurfaced caveat, an invented figure, a refusal that stopped refusing, and the rounded-number bug. Only one card runs this: the one that changes the figure gate itself.

eval · full

A live run, $1.51. Measured on 14 September on the new suite — eleven questions, eleven live turns, nothing unscored. It replaces an estimate of $1.84, which replaced $2.90 for the old suite. Happens on three cards now, all of them phase closes — the two that changed the trust machinery are both done. Two runs per card maximum — one to see the problem, one to confirm the fix. A third failure means the card is wrong, not the code.

What could go wrong, and what the plan does about it

A card's number doesn't moveIt says so in the close-out and names the cause. P1.b did exactly this. The next card is not started until the cause is written down; the answer is never "try harder".
A session wants to rebuildThe protocol says stop and ask; the default is no. If it happens twice on one card, that card is wrong and a Fable review session rewrites it.
Two sessions in one treeIt has happened. Every card commits before it ends; a session checks git log against its start; a swept commit is named in the close-out, not rewritten.
Runs flapStyle checks flap and trust rows do not — leading with a reading was every non-trust failure across four runs of the old suite. The new one reports style as a rate and only asserts it behind a flag, which a card should not set.
A deploy takes production downP0.4 made the deploy migrate itself and /health tell the truth. A card with a migration is pushed in the morning, watched five minutes, and the close-out says so.
You stop dogfoodingThen the plan is measuring itself. Five minutes a morning is the whole cost; the log's Open list is the only thing that reorders the cards.

The foolproof part is not the cards. It is that every session starts by reading one file, does one thing, and ends with a number, and that you only ever say what's wrong. Everything else is written down where the next session will find it.
